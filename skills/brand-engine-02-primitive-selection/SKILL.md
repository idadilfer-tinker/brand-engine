# Stage 2 -- Primitive selection

Read `../_shared/protocol.md` first.

## What this is for

This stage narrows to the small set of elements -- shapes, motifs, gestures,
never more than four -- that will carry the brand. It reads the Discovery
Brief first; it doesn't re-run equity or competitor analysis.

## Triage

If no Discovery Brief exists yet, route back to
`brand-engine-01-discovery` before doing anything here -- primitive choice
without a Discovery Brief is guessing, not selecting.

## Diagnosis

- From the Discovery Brief's equity, which elements are strong enough to
  evolve, and which should be retired?
- If building from zero, what does the positioning statement or category
  gap suggest as a starting shape or gesture -- not a finished mark, just a
  direction?
- For each candidate primitive, has it been tested against at least one
  format from the Discovery Brief's 12-month list, not just the format in
  front of the team today? If not, that's the single highest-leverage
  question to ask next.
- Is the client trying to keep more than four primitives alive? If so, push
  back -- more primitives with looser rules underperform fewer primitives
  with tighter ones (see `docs/methodology.md`, "fewer primitives, tighter
  rules").

## Closure conditions

Only produce the Primitive Brief once:

- 2-4 primitives are named, each distinct enough to be recognizable alone.
- Each has been checked against at least one non-obvious format.
- It's clear which primitives are evolved equity vs. newly introduced.
- Any primitive that didn't survive the format test has been dropped, not
  quietly kept.

## Formal artifact: Primitive Brief

Use the shared output shell. Stage-specific content:

- **Current judgment**: the final primitive set and one line on what each
  one is meant to carry (e.g., "the Seal carries judgment, the Stroke
  carries craft").
- **Key evidence**: which format each primitive was stress-tested against,
  and what broke or held.
- **Primary thread**: the biggest open risk in the set -- usually either
  "two primitives compete for the same job" or "one primitive has no format
  it's been tested in yet."
- **What not to do yet**: don't define shared tokens yet if a primitive is
  still shaky; don't add a fifth primitive to cover an edge case -- extend
  the rule set later instead (that's stage 4's job).
- **Recommended next step**: `brand-engine-03-dna-definition`.
- **Key conclusions for next skill**: the final primitive list, each one's
  intended job, and any known tension between them that the shared DNA
  needs to resolve.
